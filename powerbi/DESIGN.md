# Northbridge Lending credit risk dashboard: design and implementation notes

Everything is generated by [`scripts/build_pbip.py`](../scripts/build_pbip.py). Re-run it after changing the script, open
`Northbridge.pbip` in Power BI Desktop (November 2025 release or later) and click **Refresh** (about 45 seconds). The data
folder is the `DataFolder` parameter (Transform data → Edit parameters); it points at `data_clean/powerbi/`, written by
`scripts/export_powerbi.py`.

## Look: midnight banking platform

Dark, institutional design in the style of a bank's risk intelligence platform:

* **Surfaces:** midnight page (#0A1222), raised navy cards (#111C2E), a darker sidebar (#070D19), hairline borders
  (#1F2E47). No white backgrounds anywhere: charts, tables, matrices, slicers and tooltips are all dark (theme
  `theme/Northbridge_Midnight.json`).
* **Accents:** teal (#2DD4BF) and cyan (#22D3EE), used sparingly (active page, KPI accent, key series); muted cyan
  (#2A9DB0) for the main data series.
* **One type family:** Segoe UI, Semibold for titles and numbers.
* **One colour meaning everywhere:** green = within appetite / Stage 1 / current, amber = watch / Stage 2 / 30-60 days
  late, red = breach / Stage 3 / 90+ days late, tuned to read on dark.
* **Risk appetite flags** on the KPI tiles (green / amber / red against illustrative board limits: 24-month default rate
  9%, net loss 5% of lent, arrears 4% of balance, ECL coverage guide 5%, Stage 2 share 12%, backtest within ±10%), as DAX
  measures (`RAG …` text and `RAG … Color`), so they react to the filters; legend in the sidebar.
* **Page fit:** 1280 × 720 (16:9, fits laptop screens), 184 px sidebar, 16 px margins and 12 px gutters. Every table and
  matrix gets explicit column widths (money columns wider, percentages narrower) so it fills its card instead of
  sizing to its content.

## Data model

```
   dim_month ◄── fact_loan_month (loan × month: status, days past due, paid, balance)  ──► dim_loan
       ▲    ◄── fact_recovery   (loan × month: cash recovered after charge-off)        ──► dim_loan
       └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ (inactive: dim_loan[issue_month], used by [Originations])
                                     fact_ecl (loan × reporting date: stage, EAD, PD, LGD, ECL) ──► dim_loan
   dim_mob, dim_scenario (disconnected axes) · score_bands, scorecard, model_metrics, truth_check,
   ecl_backtest, fact_stage_migration, dq_log, findings (stand-alone)
```

| Table | Grain | Source |
|---|---|---|
| `dim_loan` | loan (50,000) | loan attributes, bands, score and PD, outcome (default month, 12/24-month flags, charge-off, recoveries), Dec 2025 stage |
| `fact_loan_month` | loan × month (1.16M) | `fact_loan_month.csv.gz`, decompressed in Power Query (`Binary.Decompress`) |
| `fact_recovery` | loan × month | recoveries after charge-off |
| `fact_ecl` | loan × reporting date | `ecl.py` at Dec 2024 and Dec 2025, with the three scenario ECLs |
| `dim_month` | month | unemployment and policy rate |

Every filter is a column of `dim_loan`, so it reaches every loan-level table. The month tables relate to `dim_month`;
`dim_loan[issue_month] → dim_month` is inactive (an active one would create two paths) and `[Originations]` switches it on
with `USERELATIONSHIP`.

## Measures worth noting

* **Default Rate 24m** = `SUM(default_24m) / COUNT(default_24m)`: the flag is blank for loans issued less than 24 months
  before the data ends, so they are left out instead of counting their early defaults but not their non-defaults.
* **Cum Default Rate** (vintage curves) is computed from `dim_loan` against the disconnected `dim_mob` axis, and returns blank
  past the age the youngest loan in the selection has reached, so a curve never mixes cohorts of different ages:
  `IF ( m > MIN ( dim_loan[months_available] ), BLANK (), DIVIDE ( CALCULATE ( COUNTROWS ( dim_loan ), NOT ISBLANK ( default_mob ), default_mob <= m ), [Loans] ) )`.
  (`NOT ISBLANK` matters: in DAX a blank compares as 0, so `blank <= m` is true.)
* **Roll Rate** (matrix: status this month × status next month) divides by the rows with a known next month, with
  `REMOVEFILTERS` on the column field.
* **ECL measures** filter `fact_ecl[asof]`, so the stage table, the scenario chart and the largest-loss table show Dec 2025
  while the migration and backtest tables compare with Dec 2024.

## Pages

| Page | Content |
|---|---|
| Portfolio | KPIs; open balance by payment status (month tooltip); new lending by quarter; the book by grade with ECL coverage |
| Risk Drivers | default rate by purpose, credit score, DTI and income band; the July 2023 DTI policy change |
| Vintages & Economy | cumulative default curves by year issued; roll-rate matrix; default starts vs unemployment |
| Scorecard | calibration by score band; model comparison (AUC, Gini, KS); the points table; truth check |
| IFRS 9 ECL | ECL by stage (PD, LGD, EAD, coverage, Dec 2024 coverage); scenarios; stage migration; largest expected losses (loan tooltip, drill-through) |
| Data Quality | every cleaning fix next to the number of problems injected |
| Loan Detail | drill-through on a loan: payment history (balance and days past due), applicant profile, month-by-month table |
| Grade Detail | drill-through on a grade: the grade against all grades, balance by status, default by purpose, vintage curves, its largest expected losses |

## Interactivity

* **Reset filters**: a sidebar button using Power BI's *Clear all slicers* action. The year, grade and channel slicers
  are synced across pages, so one click clears them everywhere. (A bookmark would hard-code each slicer's state and
  silently stop resetting a slicer added later.)
* **Report-page tooltips**: *Month* on the monthly charts (balance, new lending, unemployment, Grade Detail balance);
  *Segment* on the grade table and every Risk Drivers chart (loans, lent, rate, default, net loss, ECL coverage for the
  hovered grade, purpose, policy group or band); *Loan* on both largest-loss tables (loan, status, amount, balance,
  PD, ECL).
* **Drill-through**: right-click a grade → Grade Detail; right-click a loan → Loan Detail (also from Grade Detail, so
  book → grade → loan works in two clicks). *Open grade detail* / *Open loan detail* buttons do the same once a row is
  selected; until then their tooltip says what to select.
* **Cross-filtering** is on for every visual: clicking a bar, a grade row or a matrix cell filters the rest of the page.
* **Whole-book tiles** are tagged so nobody expects them to follow the slicers.

## Validation

* PBIR JSON validated against Microsoft's published schemas (0 errors); TMDL parsed with Power BI Desktop's own
  `TmdlSerializer`.
* After refresh, DAX checked against Python: 50,000 loans, $797,006,300 lent, 4,666 defaults, open balance $172,625,327,
  ECL $6,483,130, roll 30 → 60 days 51.4%, 2023 vintage 10.06% at month 24, 12 of 12 cleaning checks matched.
